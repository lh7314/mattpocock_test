# 参加团队试用 · 从这里开始（START HERE）

规则包：**RP-V4.0（仍是 DRAFT_PENDING_OWNER）**。这次试用不会改任何业务数字，也不会把规则包定版。

---

## 30 秒版

1. 双击 `D:\GAMING_NRE_AGENT\web\index.html` → 点「**参加团队试用**」。
2. 在 C1–C5 里选**一个**案例，点「载入并运行」。
   项目名、Key Factors、Wave 会自动填好并**锁定**——不用你输，也改不了。
3. 看结果。想看更细就点「打开完整结果页」。
4. 回答页面上列出的问题。**只有你这条案例真正涉及的**问题才会出现：
   案例没跑到的东西一律不问你，也不会替你把空白当成同意。
   差异格是**四选一**（附表正确 / 主表正确 / 按条件区分 / 无法判断），
   并且**必须写理由**——选了却不写理由，导出按钮不会亮。
5. 填**姓名**和**日期**（这两项不填，导出按钮不会亮）。
6. 点「导出试用提交件」，得到一个文件：`trial-submission-<案例项目名>-<时间>.json`。
7. 把**这一个文件**拖进 `D:\GAMING_NRE_AGENT\feedback_inbox\`（见 `DROP_FILES_HERE.txt`）。
8. 收卷的人跑：`python tools\collect_trial_feedback.py`

不需要装任何东西、不需要网络、不需要登录，数据不出你这台机器。

| C5 | 11 | + ORI-16 |

其余 Owner 问题在页面底部的折叠区里，**可空**：知道就答，不知道留空。
整个试用合起来覆盖 19/19 条，任何人都不需要独自回答 19 条。

写回答的口径：

- **差异格（v4.1）= 四选一 + 必填理由**：
  `附表正确`＝附表那个数就是业务上正确的数量（维持现在采用的值）；
  `主表正确`＝主表推算才对，附表要更正；
  `按条件区分`＝要看条件，请把条件写进理由；
  `无法判断`＝现在判断不了（**不算同意**，也不会取消这条差异）。
- 其余 Owner 问题仍按文字回答：`同意` / `不同意，因为……` / `待确认，缺 XX 证据` —— 都行；
- 写别的话也可以，原样保留，回收端只按字面判断，**不会**把含糊话折算成同意；
- **留空 = 没回答**，会出现在缺口清单里，不会让任何一条问题通过。

## 不方便用网页的人（备用通道，标准完全一样）

1. 按 `trial_kit\ROSTER.md` 的项目名与 Key Factors 在 `web\new.html` 手输（C5 记得把
   cpu 第 5 条、panel 第 3 条的 Wave 选「后续波次」——这个波次只是案例预设的试用假设，不是 Owner 确认）；
2. 运行分析 → 导出「试用反馈表 (CSV)」+「JSON」；
3. 填 CSV 里的 Reviewer name / Review date 和每一行答复；
4. 把**两个文件**（反馈表 CSV + `sample-analysis-*.json`）一起放进 `feedback_inbox\`。
   少了 JSON，回收端就只能证明"有人答了这组"，证明不了"这格真跑到过"。

同一项目既有提交件又有旧 CSV 时，回收端**按提交件统计**，旧文件只登记不重复计数。

## 提交前会挡你的七件事

| 检查 | 为什么要有 |
|---|---|
| 姓名已填 | 没署名的话，这条证据不能归因于任何人 |
| 日期已填 | 同上；规则包在动，没有时间点的反馈无法解释 |
| 案例已实际运行 | 没跑过就没有事实可评；不能凭想象回答 |
| 规则包版本正确 | 用旧规则包算出来的数评的是旧规则，不算本轮证据 |
| 必答题已作答 | 空白不算同意，这条是整个试用最重要的口径 |
| 每个差异格都写了理由 | v4.1 起，没有理由的选用不能当证据交给 Owner |
| 目标差异格已跑到 | 案例存在的理由就是那一格；没跑到等于没做这条案例 |

回收端 `tools/collect_trial_feedback.py` **会独立把这七条再算一遍**：
页面上的自检只是提示，真正的判据是文件里的事实。改过、伪造、过期的文件会被点名。

## 出问题了

| 现象 | 处理 |
|---|---|
| 案例列表显示"没有读到案例清单" | 跑一次 `python tools\issue_trial_forms.py` 重新生成 `web\assets\trialkit.js` |
| 头部两个规则包版本号不一样 | `python tools\run_all.py` 重新生成，别用旧页面截图反馈 |
| 导出按钮一直灰着 | 看「提交前检查」表里哪一条是 ❌，按提示补 |
| 换电脑 / 清过浏览器缓存 | 已填的草稿存在本机浏览器里，没了就重新跑一遍案例（分析本身很快） |
| 想看自己交过什么 | `feedback_inbox\` 是**只进不改**的：要改就重新导一份新时间戳的文件，不要编辑已交的文件 |
