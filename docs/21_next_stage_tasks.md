## S1 · 内核移植到浏览器（P3-1）— 无外部依赖，先做

| 项 | 内容 |
|---|---|
| 任务 | 把 `prototype/rules_v2.py` 1:1 移植为 `core/rules_v2.js`（纯函数，无 DOM、无网络） |
| 关键难点 | JS 浮点：`443.8*0.05 = 22.189999999999998`。用 `1e-9` 容差比较；**不得**用取整掩盖 |
| 验收 | ① `worked_examples_v2.json` 的 11 个用例逐个对照，所有数字差 < `1e-9`；② `SR-01`…`SR-10` 在 JS 侧全部复现，**含 `SR-09` 同样失败**；③ 移植清单（`docs/18` §3）逐项签字 |
| 不做 | 不重构算法、不"顺手优化"匹配逻辑、不改权重 |
| 工作量 | 小。逻辑已在 Python 定型，是翻译工作 |

**为什么先做**：这是唯一不依赖 Owner 输入、也不依赖 UI 的部分，且能提前暴露 JS 数值口径问题。

## S8 · 校准与观察（MVP 上线后）

| 任务 | 方法 |
|---|---|
| 区间命中率 | 记录 Owner 最终采纳的是区间上界还是下界，判断 ORI-02 该往哪边收 |
| RANGE 频率 | 统计有多少比例的分析停在 `4–5 SKU`，为 ORI-04 提供真实分布 |
| Reuse 拦截率 | 统计被 `BLOCKED_*` 挡下的复用主张，验证 DEC-06 是否过严 |
| Wave 声明率 | 多少分析真的声明了 LATER_WAVE；若接近 0，说明 ORI-03 的字段设计不合实际工作流 |

这些都是**本地导出数据的统计**，不涉及任何联网上报。
