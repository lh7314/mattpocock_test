# 11 — 设计决策记录（Design Log）

作用：把"为什么这样设计"与"依据是什么"沉淀下来，避免后续实现阶段重新争论或悄悄改口径。
每条含 **决策 / 依据 / 备选 / 状态**。状态：`已批准`（Owner 或任务书已定）、`提案待确认`、`明确排除`。

---

## DLOG-01 用户不输入 SKU 数量
- **依据**：任务 §三"用户不直接输入 SKU 数量"；工作簿行 92/95 把 `Sku 数量` 明确列在 **output** 侧。
- **实现**：UI 无 SKU 输入控件；SKU 只出现在结果页。
- **状态**：已批准。

## DLOG-02 Key Factor = 5 维（CPU/GPU/Panel/SSD/Memory）
- **依据**：行 93 `CPU GPU PANEL  SSD memory` + 行 79–83 的 5 维定义。
- **备选**：加入 ODM 作为第 6 维 → **排除**（工作簿无 ODM→数量 规则，见 ORI-05）。
- **状态**：已批准（ODM 作为记录字段，提案待确认）。

## DLOG-03 缺失值保持 `null`，绝不默认 0/1/不适用
- **依据**：任务 §三"不得自动默认为 0、1 或不适用"。
- **实现**：`KeyFactor.effective` 可为 `None`；`None` 维度从评分分母中剔除（不是按 0 计）。
- **后果**：缺失越多 → 候选并列越多 → 越容易输出范围，符合"不伪精确"。
- **状态**：已批准 + 已断言。

## DLOG-04 三值并存（文件读取值 / 用户最终值 / 本次采用值）
- **依据**：任务 §三"系统保留：文件读取值、用户最终使用值、是否发生修改、本次分析实际采用值"。
- **MVP 不做**：不采集修改原因（任务明确不要求）。
- **状态**：已批准 + 已断言。

## DLOG-05 SKU 匹配用"区间命中 + 加权"，不用决策树/产品名映射
- **依据**：任务 §五"不得只按单一字段推荐"；实测单因子无法定档（`docs/04 §F.2a`）；
  产品名作为规则违反任务红线与工作簿行 88。
- **备选 A**：决策树（if GPU>=3 then…）→ **排除**：等价于把区间硬编码，且不可解释逐维命中。
- **备选 B**：加权最近邻/回归拟合经验值 → **排除**：工作簿只有 5 个离散档位，拟合等于外推。
- **状态**：提案待确认（权重值属 Agent 设定 → ORI-08）。

## DLOG-06 并列时输出范围，不取中点
- **依据**：任务 §五"当 SKU 为范围时，样机需求同步输出对应范围，不生成伪精确的单一总数"。
- **实现**：`state=RANGE` 时 `recommended_sku = NULL`（Schema 层强制）。
- **状态**：已批准 + 已断言。

## DLOG-07 费率查表，不外推
- **依据**：`docs/05 §H.4` 实测规模经济指数 b ∈ [−0.10, +0.68]，各 Function 不同，
  任何线性外推都会失真；工作簿只有 2–6 共 5 档。
- **备选**：`rate(SKU7)=rate(SKU6)` → **明确排除**（Agent 推断升级成规则）。
- **状态**：已批准；SKU=7 需求 → ORI-13。

## DLOG-08 FVT/SIT 用查表拆分，不用全局比例
- **依据**：21 个 Function 中 17 个 FVT=SIT；仅 4 个 Certification 项不对称（Safety 甚至 FVT>SIT）。
  全局比例（如 40/60）会与其中 17 项直接矛盾。
- **状态**：已批准（由数据本身决定）。

## DLOG-09 只有 Confirmed Reuse 进入计算
- **依据**：任务 §六"Potential Reuse 只作为机会展示，不直接扣减需求"。
- **额外保护**：3 个 Function（Audio / RF Test / EMC Test）总量不随 SKU 增长，
  说明基线已内含共享假设 → 对这些行施加复用时给出"可能重复扣减"警告（`docs/05 §H.5`）。
- **状态**：已批准 + 已断言（potential 不扣减）。

## DLOG-10 `Option:` 项默认全部不启用
- **依据**：K3 原文 `remark option 的部分，还没加到样机data里面。`（Owner 已声明未纳入）+
  任务 §十"不将 Option 解释为确定规则"。
- **状态**：已批准；是否提供勾选能力 → ORI-06。

## DLOG-11 PCBA 与 unit 单位隔离
- **依据**：K3 的 8 项为 PCBA（`PCIE*1 PCBA` … `VRAM tuning*7`），与整机 unit 不可相加。
- **实现**：`unit ∈ {UNIT, PCBA}`，聚合时强制分离；已加回归断言。
- **状态**：提案待确认（是否需要在 MVP 输出 PCBA 区块）。

## DLOG-12 Risk Reserve 默认 0
- **依据**：工作簿无任何预留经验值；预填 5%/10% 等于用 Agent 猜测污染结果。
- **状态**：提案待确认 → ORI-07。

## DLOG-13 MEPA / HW PA 按"每 phase 绝对量"建模
- **依据**：B3 副表全档恒 36 / 4，且 K23 `CS: 1 phase 36 units`；
  主表 16/12/9/7.2/6 与 1/1/1/0.8/0.7 是绝对量除以 SKU 数并四舍五入的**反推产物**（16×2=32≠36）。
- **状态**：提案待确认 → ORI-10（Owner 确认前，两种口径都要展示差值）。

## DLOG-14 Certification 冲突期采用主表口径
- **依据**：主表总量公式（行 45/46）已包含 Certification 行，改口径会与 Owner 原表不可对账。
- **同时**：B2 副表数值、J33 的 source 展开式（=15）作为参照并列展示。
- **状态**：临时口径，非规则 → ORI-02。

## DLOG-15 Panel 冲突期采用行 79–83
- **依据**：与 J15 `base sku 搭配不同的panel`、行 92 `key source数量` 语义一致；
  批注的 `N*panel` 恒等于 SKU 数量，若成立则 Panel 不再是独立输入（逻辑上自我否定）。
- **状态**：临时口径，非规则 → ORI-01。

## DLOG-16 计算全部在小数下进行，禁止取整
- **依据**：**D-01（Owner 已批准）**。
- **实现**：float 存储；显示层 1 位小数；比较用 1e-9 容差；导出含全精度原值 + display 列。
- **状态**：已批准 + 已断言。

## DLOG-17 波次（Current / Full Project）为**用户声明**，非系统判定
- **依据**：全文仅行 80 一处括注，无判据。
- **实测**：同一输入 `2/2/1/2/2`，声明第二波 → Current 3 SKU / Full 4 SKU；未声明 → 4 SKU。
- **状态**：提案待确认 → ORI-03。

## DLOG-18 结果默认页隐藏 Rule ID / 公式 / 单元格
- **依据**：任务 §七"默认结果页保持精简……保留在后台数据或可展开详情中"。
- **实现**：`详情` 抽屉 + JSON 导出包含全部证据；UI 顶部仅显示基线版本与未关闭冲突数。
- **状态**：已批准。

## DLOG-19 不做任何平台化能力
- **依据**：任务 §七 明列排除项。
- **明确排除**：登录/SSO、用户目录、组织映射、RBAC、审批流、管理后台、多系统集成、通知、协作评论、规则在线编辑器。
- **状态**：明确排除（AC-18 走查项）。

## DLOG-20 前端计算，规则随应用打包
- **依据**：小工具形态 + "默认禁止使用互联网"；纯本地静态站最易分发且数据不出机器。
- **备选**：本地 Python 服务 → 排除（增加安装成本，无收益）。
- **风险**：Python/JS 双实现口径漂移 → 以同一 `baseline_v1.json` + 同一组回归用例做黄金对照（AC-7）。
- **状态**：提案待确认。

## DLOG-21 规则状态机取代"隐性取舍"
- **依据**：任务要求"所有推断标明依据、适用范围和不确定性"。
- **实现**：`CONFIRMED / DRAFT / CONFLICTED / DISABLED / NON_NORMATIVE / HISTORICAL_REFERENCE / NOT_A_RULE`
  七态（`schema/rule.schema.json`），任何非 CONFIRMED 规则都必须在 UI 暴露。
- **状态**：提案待确认。

## DLOG-22 分析记录不可被规则升级追溯改写
- **依据**：Owner 需要能回答"当时为什么给 443.8"。
- **实现**：记录内嵌 `rule_version` + `source_sha256` + 输入快照。
- **状态**：提案待确认。
