## D. 技术实现

| # | 限制 | 说明 |
|---|---|---|
| D1 | 前端计算内核是 Python 内核的**移植**，非同一实现 | 由 24 例全字段一致性检查兜底；不一致即交付阻塞 |
| D2 | 业务数值以 `rulepack.js` 内嵌（102 KB） | `file://` 下不能 `fetch()` 本地 JSON；代价是换规则包需重新生成该文件 |
| D3 | 历史依赖 `localStorage`（约 5 MB 上限） | 每条记录含完整 payload，实测约 200 KB；存满会提示 |
| D4 | 仅保证 Chromium 系（Edge/Chrome） | 无头检查也只用 Chromium |
| D5 | `verify_integrity.py` 的 Web 两项检查依赖本机可用浏览器 | 缺失时**明确跳过并在报告中标注**，不假装通过 |
| D6 | Python 侧要求 3.11+（`X \| None` 语法） | 本机为 3.14 |
| D7 | `jsonschema` 缺失时 `SC-01..SC-10` 跳过 | 打印 `[skip]`，不当作通过 |
| D8 | 时间戳用 UTC ISO8601；导出时刻用本地时区 | 便于与人核对，不影响计算 |

## F. 有意为之、不是缺陷

- `SR-09` **永久 Expected Fail**，直到 Owner 给出真实样本。意外转绿 = REGRESSION。
- Certification 不一致时**仍然输出单值 + 请确认**，而不是退化为区间（口径见 ORI-02a）。
- 不做业务取整：`443.8` 就是 `443.8`，`65.49999999999999` 在存储与导出中原样保留。
- 用户临时采用值**不落规则库**，只随本次分析保存与导出。
