### 3.2 语义差异（这才是本次修正的内容）

| 维度 | 旧模型如何解释 | Owner 补充了什么 | 新模型如何计算 |
|---|---|---|---|
| 主表 vs 附表 | 两套**互斥竞争**模型（外加 J33 第三套），无法选择 → `UNRESOLVED`、`adopted_absolute = null` | 主表是**单 SKU 用量**，附表是**该 SKU 数下的总量**，二者是同一个模型的两端 | 主表每 SKU 数量 × SKU 数 = 采用值；附表只做逐格校验 |
| 项目总量 | 每个 SKU 档都发布区间（因为 Certification 无法定价） | 附表**不得再次加入**项目总量 | 单一总量；`counted_in_project_total_times = 1`、`appendix_… = 0`（Schema `const` 锁定） |
| 范围原因 | `CERTIFICATION_MODEL_UNRESOLVED` | 范围只应来自 SKU 档位本身 | 只允许 `SKU_NOT_ESTABLISHED`；两个旧标签进入 `PROHIBITED_RANGE_REASONS` |
| FVT / SIT | 未明确 | 各读各的主表源行，**禁止全局 Phase 比例** | Schema `phase_ratio_used: null`；FVT 份额随 SKU 变动（探针 `CT-V2-07`） |
| J33 | 第三套竞争模型（不可求值的 candidate） | 不应叠加，也不应因此强迫 MVP 增加输入 | `BREAKDOWN_EVIDENCE` + `DECLARED_NOT_GENERALIZED`，`additive = false` |
| 逐格验证 | 无 | 附表是验证依据 | 40 格逐格 `VERIFIED / MISMATCH / NOT_EVALUABLE` + 原值 + delta |

### 3.3 哪些数字变了、哪些没变、为什么

| 类别 | 内容 | 变了吗 | 为什么 |
|---|---|---|---|
| **① 因 Certification 语义修正而变化** | 输出形态与状态：区间 → 单值；范围原因 → 仅 `SKU_NOT_ESTABLISHED`；新增逐格验证与 ORI kind | **形态变，数值不变** | Phase 2 的上界本就用主表；附表降级为验证证据 |
| **② 因 MEPA / HW PA 模型（Phase 2）而既有变化** | 2 SKU +8.0、6 SKU −0.4（4 格） | **未变（沿用 Phase 2）** | 本任务未触碰；仍待 ORI-10 |
| **③ 与 Certification 无关且保持不变** | 38 个格逐格等于 Workbook，含 65.49999999999999 与 443.8 | **未变** | 未修改任何源数据；探针 `RT-01` 守护 |
| **④ 仅由 SKU 范围引起的范围** | 4 SKU 443.8 ↔ 5 SKU 474.0，宽 29.2 | **未变（行为按 DEC-01 保持）** | SKU Definition 的结构性子集，ORI-04 |
| **⑤ 由源数据不一致引起的 Review 结果** | 7 格 MISMATCH（Green SIT@3、Safety FVT@6、RF SIT 全档） | **新增（本次首次逐格量化）** | 附表与主表都是自洽的业务数字，须 Owner 裁决 |
