## Q-01 七处主表 / 附表差异，是否由源表作者更正主表列？（最高优先）

- **要回答什么**：40 格里 7 格 `主表单 SKU 数量 × SKU 数 ≠ 附表总量`（明细见
  `docs/36_certification_adoption_v4.md`）。DEC-10 已经决定"用哪一列"，但**没有解释为什么两列不等**。
- **为什么重要**：这是唯一还会改变项目总量的开放问题；也决定 ORI-02 能否关闭、规则包能否定稿。
- **当前临时处理**：采用附表；主表值与派生值原样保留为审计；差值逐格上报，不改源表、不取整。
- **选项**：(A) 附表为业务正式量 → 请源表作者修主表 7 格；(B) 主表正确 → 需重新决定采用口径；
  (C) 两列描述不同 Source 组合 → 请给出选择判据（哪个项目用哪一列）。
- **Agent 建议**：先走 (A)。`Green/SIT/SKU3`（主表 3.0，相邻档都是 6/N）最像录入错误，
  可先从它验证判断。
- **影响**：当前 SKU2–SKU6 总量已含此决定：366.0 / 408.0 / 438.8 / 469.0 / 502.0；
  若改回主表口径则为 373.0 / 417.0 / 443.8 / 474.0 / 506.6（差 7 / 9 / 5 / 5 / 4.6 台）。

## Q-02 4 SKU 与 5 SKU 的真实分界条件 ⭐

- **要回答**：什么样的配置应判 4 SKU、什么判 5 SKU？
- **为什么重要**：现在同组输入得到 `RANGE 4–5`，两档都算但不知选哪个。
- **当前临时处理**：输出范围，`preferred_sku = NOT_ESTABLISHED`，绝不默认一档。
- **选项**：提供 2–3 个真实项目"配置 + 实际 SKU 数"即可建立规则；或明确"4–5 一律人工决定"。
- **Agent 建议**：给样本即可。4 SKU 定义是 5 SKU 定义的子集，**没有样本无法自动分界**（探针 SR-09 保持红色）。
- **影响**：两档差 **30.2 台**（438.8 对 469.0）。

## Q-03 MEPA 是否恒为每 Phase 36；HW PA 何时饱和于 4 ⭐

- **当前临时处理**：`PER_PHASE_FIXED`（界面显示"临时采用"）。
- **选项**：(A) 恒为 36 / 4；(B) 给出真实规则（与 SKU 数或 Build 数关系）。
- **Agent 建议**：请业务确认 36 是"每 Phase 固定"而非"某档读数"。
- **影响**：SKU2 **+8.0 台**、SKU6 **−0.4 台**（其余档位为 0）。

## Q-04 EMC Test / NV / INTEL 的平坦总量是不是固定量

- **当前临时处理**：保持 `PER_SKU_RATE` 并登记 6 条模型问题；**不因形状平坦就改模型**。
- **影响**：若确认是固定量，SKU2 与 SKU6 的总量会各自改变（合计约 ±11.9 台量级），需重算。
- **Agent 建议**：逐 Function 回答"总量恒定"或"每 SKU 数量恒定"。

## Q-05 Risk Reserve 的比例与基数

- **当前临时处理**：默认 0；填写时只对基线需求计提，不对用户追加需求计提。
- **影响**：4 SKU 上 5% = **21.94 台**。
- **Agent 建议**：给一个团队默认值并注明基数，界面保留手动修改。

## Q-06 波次判据在哪里维护

- **当前临时处理**：只有用户显式标记 `LATER_WAVE` 才排除；"未特别指定"计入当前波次；
  波次永不改变同一 SKU 档位的 base_demand。
- **影响**：需求表出现波次标记列后，Current Wave 才会与 Full Project 真正分叉。
- **Agent 建议**：在需求表加"波次"列，规则包按列取值。

## Q-07 导出文件是否需要"采用值来源"标注

- **当前状态**：JSON / Review CSV / 试用反馈表**已经**同时给出采用值（附表）、
  主表值、主表派生值、差值，以及"计入次数 1 / 0"。
- **要回答**：格式是否够用？是否需要按 Function 汇总的简版？
- **Agent 建议**：先按现格式试用一轮，用反馈表第 5 段回复。

## Q-08 主表口径是否长期作为审计保留

- **当前临时处理**：永久保留（Schema 与探针都固定了"审计值计入 0 次"）。
- **选项**：(A) 长期保留；(B) 主表更正后关闭审计列。
- **Agent 建议**：(A)，成本仅是一个展开详情；一旦哪天又改口径，差异链条仍可追溯。

## Q-09 ODM 差异规则是否入规则包

- **当前临时处理**：规则包只含单一基线（CS ODM），3 处 Status 文本原样保留，不推断。
- **选项**：提供规则文本 / 表格；或确认"一个 ODM 一张基线表"。

## Q-10 天线源 / WLAN 数量是否要在 MVP 采集

- **当前状态**：不采集。J33 只作解释证据，`mvp_requires_antenna_wlan_input_now = false`。
- **选项**：(A) 暂不采集（附表采用值与该组合无关）；(B) 需要按组合取数 → 需给出取数规则。

## Q-11 团队试用反馈表是否够用

- **当前格式**：`trial-feedback-<项目>-<时间>.csv`，5 段：本次结果逐项确认 /
  主表与附表仍不一致的格子 / 本次登记的待确认问题 / 19 条唯一 Owner 问题 / 界面与流程反馈。
- **Agent 建议**：试用 3–5 条真实分析后回收反馈表 + JSON，作为规则包定稿证据。
