## 第 2 题 · ORI-04 — 4 SKU 与 5 SKU 的真实分界条件

**问题**：什么条件下应判 **5 SKU** 而不是 **4 SKU**？能否提供真实 4 SKU 项目与 5 SKU 项目各若干，
以及正式分界规则？

**为什么需要确认**：SKU Definition 行 82（5 SKU）是行 81（4 SKU）的**严格子集**。
在 405 组真实合理的配置组合中，**5 SKU 作为唯一最优解出现 0 次**。
这不是算法问题，是定义本身的结构缺口，只有真实样本能补上。

**当前临时处理**：输出 `4–5 SKU` 范围；`recommended_sku = null`、
`preferred_sku = NOT_ESTABLISHED`；两档都完整计价；页面并列展示、不预选、不用颜色或排序暗示。
回归探针 `SR-09` 按设计**永久 FAIL**，另有 `EF-01` 保证 Expected Failure 集合恒等于 `['SR-09']`。

**可选方案**：
- **(A) 提供真实 4/5 SKU 样本 + 正式分界条件** → 可关闭，`SR-09` 自然转绿。
- **(B) 确认 5 SKU 不是独立档位**（应合并或删除该定义）→ `SR-09` 按新口径重写（不是删除）。
- **(C) 维持范围输出** → 每次都人工在 4 与 5 之间选，工具不代选。

**Agent 建议**：**(A)**。任何权重调整都只是掩盖问题，且已被 `SR-10` 冻结禁止。

**不确认会怎样**：只要关键配置落进 4/5 并列区，样机需求就是一个区间
（**4 SKU 443.8 台 ↔ 5 SKU 474.0 台，相差 29.2 台**），而不是单值；规则包不能定版。

## 第 3 题 · ORI-10 — MEPA 是否各档恒为每 Phase 36？HW PA 在几 SKU 后饱和于 4？

**问题**：MEPA 附表各行恒为 36 —— 是否表示各 SKU 档位都是每 Phase 36？
HW PA 附表为 `2,3,4,4,4` —— 是否表示 4 SKU 起饱和于 4？

**为什么需要确认**：这是当前**唯四**与 Workbook 自身算术不一致的格，
直接决定 2 SKU 与 6 SKU 两个档位。

**当前临时处理**：采用附表绝对量（`PER_PHASE_FIXED` 候选模型），前端显示「临时采用」；
不使用"除以 SKU 再乘回"的伪费率。

**可选方案**：
- **(A) 附表绝对量正确** → 转 `CONFIRMED`，同时承认 MEPA 不随 SKU 变化。
- **(B) 主表费率正确** → 回退 `PER_SKU_RATE`（会撤销 Phase 2 对这两格的处置）。
- **(C) MEPA 用 (A)，HW PA 用饱和模型** → 请给出饱和点（4 SKU？）。

**Agent 建议**：**(C)**。附表那 6 个整数（36 / 36 / 2/3/4/4/4）比 `4.2` 这类回推小数更像业务原意。

**不确认会怎样**：2 SKU 档多算 8.0 台、6 SKU 档少算 0.4 台；规则包不能定版。

## 第 4 题 · ORI-02a — 「Certification 源费率已验证」是指规则还是逐格数据？

**问题**：您要求"输出单值必须满足 Certification 源费率已验证"。这里的"已验证"是指
**(A) 计算规则已验证**，还是 **(B) 每一格的附表校验都通过**？

**为什么需要确认**：本次任务必须在这两种读法之间选一个才能落地。

**当前临时处理**：按 **(A)** 实现 —— 输出单值 + 逐格披露验证状态 + 允许本次分析临时采用值。

**可选方案**：**(A)** 确认规则层口径（现状）；**(B)** 改为逐格口径 → 那么
Green / Safety / RF Certification 三个 Function 将不能输出单值，需同步修订测试预期。

**Agent 建议**：**(A)**。理由：单值 + 显著差异披露比人为制造区间更可用；
而且一旦按 (B)，7 格里任一格未通过就会让整个项目总量退化为区间，回到 Phase 2 的老问题。

**不确认会怎样**：任务 §24 的 `CT-V2-03`（单一 SKU 时 Certification 输出单值）
与 §8 的"源费率已验证"之间存在解释分歧，规则包定版时需要重新对齐。

## 第 5 题 · ORI-02b / ORI-17 — Certification 主表数值的真实语义

**问题（两小问）**：

**(a)** J33 描述的 SRRC / CE / FCC / 印尼 / Mexico / 资安 整机需求，是否**已经包含**在主表 RF 的 15 里？
**(b)** `Safety/SIT`（恒 6）与 `RF/SIT`（恒 15）的主表"每 SKU 数量"随 SKU 严格 1/N 递减，
这更像"总量按 SKU 摊分"而不是"单个 SKU 所需数量"。真实语义是哪一个？

**为什么需要确认**：本次任务已确认 J33 **不是**第三套模型，也**没有**把它叠加到结果上。
但如果 J33 其实是"尚未包含的补充项"，那 RF Certification 就被低估了。
(b) 决定"未来新增 SKU 档位时如何外推"。

**当前临时处理**：J33 登记为 `BREAKDOWN_EVIDENCE` / `DECLARED_NOT_GENERALIZED`，
`additive = false`，MVP **不**新增天线 / WLAN 输入项。
(b) 按您的指令执行 `每 SKU 数量 × SKU 数`，对这两格结果恰等于恒定总量，数值无歧义。

**可选方案**：
- (a)：**(A)** J33 只是构成说明，15 已包含 → 归档；**(B)** J33 是独立补充 → 需定义叠加规则；
  **(C)** J33 与附表对应不同 Source 组合（归入第 1 题的 (C)）。
- (b)：**(A)** 表内数值就是单 SKU 用量，1/N 只是填表习惯 → 归档；
  **(B)** 这两格语义是"Phase 总量" → 改标 `PER_PHASE_FIXED`（数值不变，与 MEPA 同处理）。

**Agent 建议**：(a) 选 **(A)** 或 **(C)**，不建议 (B)（无任何判据可确定叠加条件）；
(b) 选 **(B)** 在标注上更诚实且**不改任何数字**。

**不确认会怎样**：RF Certification 存在被低估或（若将来误叠加）被重复计入的风险；
主表语义含糊会在扩展 SKU 档位时突然变成实际数值差异。

## 第 6 题 · ORI-01 — Panel 批注 `N*panel` 到底是什么意思？

**问题**：`D2:H2` 的 `2*panel / 3*panel / 4*panel / 5*panel / 6*panel` 与 SKU Definition
行 79–83 的 Panel spec 数量 `[1-2] [1] [2] [2] [2-3]` 冲突。哪个是业务口径？

**为什么需要确认**：这是 SKU 推荐的一个输入维度。若批注才是真值，SKU3–SKU6 的判定会全部改变。

**当前临时处理**：按 Panel **Spec Count**（行 79–83）匹配；批注整体降级
`UNRESOLVED_COMMENT`，在导出中回显但不参与任何计算；Panel 输入维度保留未删。

**可选方案**：**(A)** 批注只是"送样 N 份"的注释，与 SKU Definition 无关 → 可直接关闭；
**(B)** 批注是 Panel 维度真值 → 需重写 SKU Definition 并重跑全部 SKU 探针；
**(C)** 批注适用于另一个维度（例如送样份数）→ 需新增输入项并定义用途。

**Agent 建议**：**(A)**。反例证据：`panel=1` 时系统给出 3 SKU，若 `E2 = 3*panel` 参与匹配则不可能成立。

**不确认会怎样**：不影响当前数量结果，但规则包不能定版；导出中会持续显示被排除的批注证据。
