把试用产物丢进这个文件夹（DROP FILES HERE）
================================================

推荐通道（网页试用模式）
------------------------
把 `web\trial.html` 导出的**一个**文件复制进来：

    trial-submission-<案例项目名>-<时间>.json

它已经包含了分析输入、分析结果、规则包版本、实际跑到的差异格、
你的回答、姓名与日期。不需要再补别的文件。

备用通道（不用网页）
--------------------
两个文件一起放进来，缺一个就只能证明"有人答了"、证明不了"这格真跑到过"：

    trial-feedback-<项目名>-<时间>.csv          （导出的试用反馈表，已填写）
    sample-analysis-<项目名>-<时间>.json        （同一次分析的 JSON 导出）

同一项目如果既有提交件又有旧 CSV，回收端按提交件统计，旧文件只登记不重复计数。


规矩（很重要）
--------------
1. 只新增，不改。已经交进来的文件是证据，不要回来编辑；
   答错了就重新导一份新时间戳的文件，让两份都在，回收端会按字面统计并提示冲突。
2. 空白不算同意。没答的问题会留在缺口清单里，不会替你通过任何一条。
3. 姓名和日期缺任何一个，这份文件都会被标为 UNATTRIBUTED，不能当定稿证据。
4. 不是当前规则包（RP-V4.0）产出的文件，会照常统计，但明确标注**不作为定稿证据**。
5. 空白反馈表留在 `trial_kit\forms\`，不要在这里就地填写。
6. 除上面列出的文件类型外，别的文件放进来会被点名并要求移走——
   这是为了防止"看起来收上来了，其实一行答复都没有"。

收卷
----
    python tools\collect_trial_feedback.py

报告写在 `artifacts\validation\trial_feedback_report.md`。
回收端会独立重算姓名、日期、是否真的跑过、规则包版本、必答题、
以及目标差异格是否真跑到——页面上的自检只是提示，判据是文件里的事实。
